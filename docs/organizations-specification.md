# Организации

Организация — компания продавца, за которой стоят один или несколько аккаунтов маркетплейсов. Ключ — ИНН:
у одной организации могут быть магазины на разных площадках и несколько магазинов на одной. Понятие шире
юрлица — индивидуальный предприниматель тоже организация (ИНН из 12 цифр, ОГРНИП вместо ОГРН).

Организация — основа для учёта кодов маркировки «Честный знак»: коды принадлежат участнику оборота, а не
отдельному магазину.

## Модель данных

```
Organization : IHasIdentity
├── Id              — Guid
├── Name            — string, отображаемое название
├── Inn             — string, уникальный индекс IX_Organizations_Inn
├── LegalName       — string?, полное наименование
├── Kpp             — string?
├── Ogrn            — string?, ОГРН или ОГРНИП
├── OwnershipForm   — string?, ООО / ИП / …
├── CreatedAt       — DateTime
├── CreatedById     — Guid? → ApplicationUser (SetNull); null у созданной синхронизацией
└── Accounts        — MarketplaceAccount[]

[Projectable] SearchString => Name + " " + LegalName + " " + Inn
[Projectable] Kind         => Inn.Length == 12 ? SoleProprietor : LegalEntity
```

**`Kind` (`OrganizationKind`: `LegalEntity` / `SoleProprietor`) не хранится — он выводится из длины ИНН.**
Юрлицо от ИП отличает именно ИНН, а он у организации обязателен и проверен, поэтому тип не может разойтись с
ним. `OwnershipForm` остаётся свободной строкой для показа: площадки отдают её текстом (`"ИП"`, `"ООО"`, …)
без закрытого списка, и enum превращал бы каждое незнакомое значение в «прочее».

Со стороны аккаунта — `MarketplaceAccount.OrganizationId` (`Restrict`) и `IsOrganizationLinkedManually`, см.
[marketplaces-specification.md](marketplaces-specification.md#аккаунт-маркетплейса-marketplaceaccount).

**Реквизиты организации — её собственная копия.** Аккаунт хранит то, что отдаёт маркетплейс, организация — то,
что ей задали. Синхронизация заполняет реквизиты организации только при её создании и больше их не трогает;
правка реквизитов организации не меняет аккаунты. Расхождение ИНН аккаунта и его организации видно в UI.

## Привязка аккаунтов

`IOrganizationService.LinkByInnAsync(account)` вызывается шагом «Реквизиты продавца» каждой синхронизации,
сразу после записи реквизитов:

1. Аккаунт с `IsOrganizationLinkedManually` пропускается — ручной выбор синхронизация не трогает.
2. Аккаунт без ИНН пропускается, текущая привязка сохраняется: пустой ИНН от площадки не повод её снимать.
3. Есть организация с таким ИНН — аккаунт привязывается к ней.
4. Нет — организация создаётся из реквизитов аккаунта (`Name` = наименование юрлица, а без него — имя
   магазина) и пишется в журнал с действием `organization.auto_created`, `actionData: { accountId }`.

Две синхронизации аккаунтов одного продавца могут создавать организацию одновременно. Уникальный индекс по
`Inn` пропускает только одну вставку; вторая ловит нарушение именно этого индекса
(`UniqueViolations.IsOrganizationInn`), отцепляет свою организацию и привязывает аккаунт к уже созданной.

Ручная привязка — `PUT api/integrations/marketplaces/accounts/{id}/organization` с `{ organizationId }`:

- значение закрепляет привязку (`IsOrganizationLinkedManually = true`);
- `null` снимает закрепление и сразу привязывает аккаунт по ИНН, как это сделала бы синхронизация. Аккаунт
  без ИНН остаётся без организации.

Действие пишется в журнал аккаунта как `account.organization_set`.

Миграция организаций не создаёт — у существующих аккаунтов они появляются на ближайшей синхронизации.

## API

Префикс — `api/organizations`.

| Метод | Путь | Право | Назначение |
|-------|------|-------|------------|
| `GET` | `/` | `organizations.view` | Список с пагинацией, поиск по названию, наименованию и ИНН, сортировка `name` / `inn` / `createdAt` |
| `GET` | `/short` | `organizations.view` | `id`, `name`, `inn` всех организаций — для пикера |
| `GET` | `/{id}` | `organizations.view` | Организация со списком привязанных аккаунтов |
| `POST` | `/` | `organizations.edit` | Создание |
| `PUT` | `/{id}` | `organizations.edit` | Изменение реквизитов |
| `DELETE` | `/{id}` | `organizations.edit` | Удаление, `204` |

Аккаунты в `OrganizationDto` несут собственный `inn` и `isOrganizationLinkedManually`, поэтому странице
организации не нужен доступ к интеграциям, чтобы показать расхождение ИНН.

### Права

`organizations.view` / `organizations.edit` отделены от `integrations.*`: у организации нет ключей API, а
коды маркировки, которые к ней привяжутся, — отдельная зона ответственности. Ручная привязка аккаунта
проверяет `organizations.edit`, хотя живёт в контроллере интеграций: она меняет то, к какой организации
относится магазин, и не трогает подключение. `_assigned`-вариантов нет — организация не принадлежит складу.

### Коды ошибок

| Код | HTTP | Когда |
|-----|------|-------|
| `organizationNotFound` | 404 / 422 | Организация не найдена; `422` на `organizationId` при ручной привязке |
| `organizationInnInvalid` | 422 | ИНН не из 10 или 12 цифр |
| `organizationInnDuplicate` | 422 | Организация с таким ИНН уже есть |
| `organizationHasAccounts` | 409 | Удаление организации, к которой привязаны аккаунты |

Удаление запрещено, пока к организации привязан хоть один аккаунт: FK `Restrict`, а предпроверка отдаёт
`409` вместо сырого `23503`.

### Журнал

`AppEntityType.Organization = 23`. Создание, правка и удаление пишутся через
`IChangeLogService<OrganizationDto>`; запись публикует `entityChanged` наблюдателям страницы организации.
Организация участвует в глобальном поиске (`AppEntity` с `additionalFields.inn`).

## Фронтенд

Пункт **Организации** верхнего уровня (`organizationsConfig.tsx`), под `organizations.view`.

Подпись типа — `ORGANIZATION_KIND_LABELS` в `features/organizations/organizationKinds.ts`, чип `outlined` в
списке и на странице организации.

- `/organizations` — `OrganizationsPage`: таблица с поиском (`?search=`) и сортировкой, кнопка **Добавить**
  под `organizations.edit` открывает `OrganizationFormDialog`.
- `/organizations/:id` — `OrganizationPage`: реквизиты, таблица аккаунтов (ИНН, расходящийся с ИНН организации,
  помечен предупреждением; строки ведут на аккаунт только при `integrations.view`), **Изменить** /
  **Удалить** под `organizations.edit`. `DeleteOrganizationDialog` блокирует подтверждение, пока аккаунты
  привязаны. Страница подписана на `organization` через `useEntityWatch`.
- `OrganizationFormDialog` — создание и правка; ИНН, КПП и ОГРН проверяются по длине ещё на клиенте, сервер
  повторяет проверку ИНН.
- На вкладке **Обзор** аккаунта — блок **Организация** и `AccountOrganizationDialog`: переключатель
  «Определять по ИНН» либо выбор через `OrganizationsSelect`.
