# Техническое задание — Флоу WMS

Описание основных операционных флоу системы управления складом.

---

## Флоу 1: Разгрузка фуры — приёмка товара и расстановка по ячейкам

### Описание

На склад приходит фура с товаром. Администратор создаёт приходной ордер, загружая CSV-манифест со списком ожидаемого
товара. Сотрудники физически разгружают фуру, расставляют коробки по ячейкам склада, затем подходят к каждой ячейке с
ТСД (терминал сбора данных) и вносят данные: какой товар в каком количестве лежит в этой ячейке. Система отслеживает
расхождения между ожидаемым и фактически размещённым товаром.

---

### Участники

| Участник             | Роль                                                                          |
|----------------------|-------------------------------------------------------------------------------|
| **Администратор**    | Создаёт приходной ордер, загружает CSV, следит за прогрессом, закрывает ордер |
| **Сотрудник склада** | Физически расставляет товар, вносит данные о ячейках через ТСД                |

---

### Пошаговый флоу

#### Фаза 1 — Администратор создаёт приходной ордер

1. Администратор открывает раздел «Приходы» в веб-интерфейсе.
2. Нажимает «Новый приход», заполняет метаданные: внешний номер / номер фуры, ожидаемую дату приезда, примечание.
3. Загружает CSV-манифест со списком ожидаемого товара. Каждая строка — артикул, характеристика (обычно размер одежды) и
   количество.
4. Администратор проверяет распознанный список, исправляет ошибки, активирует ордер.
5. Ордер становится виден сотрудникам в приложении ТСД.

#### Фаза 2 — Сотрудники физически расставляют товар

1. Сотрудники разгружают фуру и развозят коробки по ячейкам склада.
2. Эта фаза не требует взаимодействия с системой — чисто физическая работа.

#### Фаза 3 — Сотрудники вносят данные через ТСД

Для каждой ячейки, в которую положили товар:

1. Сотрудник открывает приложение на ТСД, выбирает активный приходной ордер.
2. Переходит к ячейке: сканирует QR/штрихкод на ячейке или выбирает её вручную из схемы склада.
3. Для каждого товара в этой ячейке вводит или сканирует артикул, выбирает характеристику и вводит количество, затем
   подтверждает размещение.
4. Переходит к следующей ячейке и повторяет.

#### Фаза 4 — Администратор закрывает ордер

1. Администратор открывает сводку приходного ордера — видит сравнение ожидаемого и фактически размещённого по каждому
   SKU.
2. Расхождения (недостачи, излишки) выделены.
3. Администратор закрывает ордер. Закрытый ордер заморожен — новые размещения не принимаются.

| 2 | Отображать ли текущие остатки ячейки (из прошлых ордеров) при размещении?   | Вне области v1                                         |

## Флоу 2: Отгрузка заказа

### Описание

Формируется заказ на отгрузку: список товаров, которые нужно собрать со склада и передать клиенту или курьеру.
Сотрудники обходят ячейки склада с ТСД и забирают нужный товар (сборка / пикинг). После завершения сборки администратор
закрывает заказ, остатки в ячейках уменьшаются.

---

### Участники

| Участник             | Роль                                                                               |
|----------------------|------------------------------------------------------------------------------------|
| **Администратор**    | Создаёт заказ на отгрузку, следит за прогрессом сборки, закрывает заказ            |
| **Сотрудник склада** | Обходит ячейки с ТСД, забирает товар, подтверждает каждое изъятие через приложение |

---

### Пошаговый флоу

#### Фаза 1 — Администратор создаёт заказ на отгрузку

1. Администратор открывает раздел «Отгрузки» в веб-интерфейсе.
2. Нажимает «Новая отгрузка», заполняет метаданные: номер заказа / получатель, дата отгрузки, примечание.
3. Добавляет позиции: для каждой — артикул, характеристика, требуемое количество.
4. Система проверяет, достаточно ли товара на складе (по текущим остаткам в ячейках). При нехватке — предупреждение, но
   блокировки нет.
5. Администратор назначает сотрудников на заказ: выбирает из списка пользователей, кто будет участвовать в сборке.
6. Администратор распределяет позиции заказа по сотрудникам вручную. Каждую позицию можно либо назначить целиком одному сотруднику, либо разбить на части: указать для каждого сотрудника, сколько единиц из этой позиции он собирает. Сумма частей должна равняться общему количеству позиции.
7. Администратор активирует заказ. Каждый назначенный сотрудник видит в приложении на ТСД только свои позиции.

#### Фаза 2 — Сотрудники собирают товар

Для каждой позиции заказа:

1. Сотрудник открывает приложение на ТСД — видит только назначенные ему позиции текущего заказа.
2. Видит список своих позиций к сборке с подсказкой, в каких ячейках лежит нужный товар.
3. Подходит к указанной ячейке, сканирует её QR/штрихкод.
4. Сканирует или вводит артикул, выбирает характеристику, вводит забранное количество.
5. Подтверждает изъятие. Остаток в ячейке уменьшается в системе.
6. Если нужного количества в одной ячейке не хватает — переходит к следующей ячейке с тем же товаром и повторяет.

**Сценарий: в ячейке физически меньше товара, чем показывает система**

1. Сотрудник подходит к ячейке и обнаруживает расхождение: система показывает, например, 10 единиц, а реально их 6.
2. Сотрудник забирает сколько есть (6), вводит фактическое количество в поле «забрано».
3. В том же экране отмечает расхождение: нажимает «Сообщить о недостаче в ячейке» и указывает реальный остаток (или 0, если ячейка пуста).
4. Система фиксирует корректировку остатка ячейки и создаёт уведомление для администратора.

#### Фаза 3 — Администратор закрывает заказ

1. Администратор открывает сводку заказа — видит сравнение требуемого и фактически собранного по каждой позиции.
2. Расхождения (недобор) выделены. Если сотрудники сообщали о недостачах в ячейках — они отображаются отдельным списком с указанием ячейки, ожидаемого и реального остатка.
3. Администратор разбирает каждую недостачу: подтверждает корректировку остатка (остаток в ячейке уже обновлён) или отклоняет (если считает данные ошибочными — остаток возвращается к прежнему значению).
4. Администратор закрывает заказ. Закрытый заказ заморожен — дальнейшие изменения невозможны.
